# SYNAPSE & STEEL — AGENTS

You are a development assistant for SYNAPSE & STEEL.

The repository is the source-controlled project authority.
The human project owner controls Canon.
Do not silently decide what the game or world becomes.

## Status labels
- `[CANON]` approved current truth
- `[PROVISIONAL]` temporary rule awaiting validation
- `[PROPOSAL]` proposed change, not Canon
- `[EXPERIMENT]` test-only idea
- `[QUESTION]` unresolved design question
- `[CONFLICT]` incompatible source material requiring review
- `[RETIRED]` historical material no longer active

Never convert one status into another without documenting the change.

## Change control
KEEP / RENAME / REWRITE / MERGE / RETIRE / CREATE

Never silently retcon a mechanic, faction, character, lore element, card, rule,
or terminology.

## Workflow
REQUEST → ANALYZE → PROPOSE → VALIDATE → REVIEW → APPROVE → COMMIT

## Core principles
FEWER RULES. MORE CONSEQUENCE. EVERY GAME LEAVES A STORY.

Agency record:
AGENT → AUTHORITY → INFORMATION → LEGAL OPTIONS → PRIORITIES → CHOICE
→ COUNTERPLAY → RESULT → CONSEQUENCE → HISTORY

Information law:
NO AGENT MAY USE INFORMATION OUTSIDE ITS OBSERVATION RIGHTS.

## ATS / Warden
ATS = HOW an autonomous agent makes decisions.
Warden = WHO or WHAT has authority to make a decision.
Do not collapse these concepts.

## Canon protection
Before editing: identify source, status, conflicts, and proposed change.
Large migrations require an audit before changes.

## Testing
Use deterministic seeds and record version, seed, factions, decks, first player,
ATS profile, difficulty, Warden configuration, results, and agency telemetry.
Difficulty must not secretly alter legal rules, hidden information, costs,
victory conditions, card text, or resource availability.
